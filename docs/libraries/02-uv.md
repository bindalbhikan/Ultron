# 2. uv — installs and a lock file

**Status**: ✅ 16 Nov 2026 (cloud runners). The office PC runner (zero TD, grouping on `bindal-office`) keeps its
own venv for now: move it to `uv sync` when next at the PC.

**Why**: installs 10-100x faster than pip (CI minutes on every one of ~40 workflows), and a lock file
(`uv.lock`) so every run, the office PC and a seller's machine get the exact same versions. Before,
`pyproject.toml` had only lower bounds: a new pandas / openpyxl release could change a run silently.

**What was done**
* `uv.lock` (77 packages) from `pyproject.toml`, extras `full`, `browser`, `workings`. Checked before the switch:
  the 21 main packages in the lock are the very versions the bots' pip install had on 16 Nov 2026 (pandas 3.1.1,
  numpy 2.5.5, openpyxl 3.1.5, requests 2.34.2, scrapy 2.20.0, xlsxwriter 3.3.1, python-calamine 0.9.1,
  curl_cffi 0.17.0, pypdfium2 5.15.2, zxing-cpp 3.1.1 ...), so no number changes.
* `.github/actions/setup` (used by every bot workflow): `astral-sh/setup-uv` (uv 0.13.8, cache on `uv.lock`),
  `uv export --frozen` of the extra, `uv pip install --system`, Ultron itself `-e . --no-deps`. The browser
  extra the same way, then `patchright install`.
* `.github/workflows/tests.yml` (**Tests**): the test suite on that same setup on every push (any branch) and
  pull request; tried on branch `libs-uv` first (run 43824646924 green) before main.

**Change a version**: edit `pyproject.toml`, run `python -m uv lock` (or `uv lock --upgrade-package <name>`),
commit `uv.lock`; the Tests workflow shows the result before the bots use it. Termux keeps pip (pure-Python core).
